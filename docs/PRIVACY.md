# Privacy and retention

No advertising, third-party analytics, automated AI messages, contact upload, public matching or mandatory real-name/photo policy. Identity is stable internally and pseudonymous externally. Age band is self-declared; this is not a certified child-safety or age-assurance service.

Private-by-default discovery, invitation-only private/minor connections, block controls, opt-in visible read cutoffs, no online presence or emitted typing status. Email is not returned by public profile projections. Optional bio/check-in fields are disclosed only after mutual Unmasked acceptance and an independent owner reveal. Hiding/ending clears active disclosure permissions; it cannot erase what another person has already seen or captured.

The server operator can read message bodies. TLS is transport protection, not E2EE. Use disk/database/backup encryption managed by the operator; this project does not configure encryption at rest. Avoid real private content on an unsecured development server. Client recent-history cache, drafts/outbox and Ideas are unencrypted on local application storage; only native refresh credentials use SecureStore. Sign-out clears account cache, drafts/outbox and cached offline profile, not separate developer Ideas. The separate Clear local cache action preserves drafts and queued messages. Browser/local backups may retain data.

Deleting an account removes the active user and dependent identity/session/contact rows, redacts authored message text and retains anonymous message tombstones in others' shared history. Existing recipient exports, screenshots and operator backups are not retractable. The optional maintenance worker deletes expired sessions/auth codes every minute. No automatic message/report retention period exists; operators must establish a documented policy before deployment. Reports retain explicitly submitted content with reporter/subject IDs nulled on deletion. Operator investigation, erasure requests and appeals require a configured human contact; no compliance certification is claimed.

Exports include authorized conversations and should be treated as sensitive files. Self-hosters must supply their own privacy notice, operator contact, lawful basis, data-subject request handling, backup retention and abuse procedure before accepting public users. The architecture is intended to support privacy obligations; it is not a claim of GDPR certification.
